# Technical Notes

- Use hexagonal architecture at all times. Keep business logic isolated from CLI, filesystem, network, storage, and other external adapters.
- Prefer functional testing before calling any feature complete. Unit tests are useful, but they do not prove the tool works the way the design intends.
- Take an agile approach to development. Avoid waterfall: underspecify when useful, prototype early, learn from the result, and refine from working behavior.
- The buildable spec is `docs/docs/explanation/design.md` (+ `docs/docs/reference/format.md` for the artifact contract). The implementation roadmap is `.journal/002/PLAN.md` (seven phases with per-phase manual gates); phases 1–6 are done and proven, only 7 (progress reporting, docs set, v0.1.0) remains.
- Resume contract (phase 4, `.journal/005/DESIGN.md`): `Blobs.Get` reports the offset the stream actually starts at — contractually `off` (range honored) or `0` (range ignored; the same attempt consumes the whole-blob body at no extra request or attempt); anything else is a port-contract violation the orchestrator terminal-guards. The continuation hasher holds WIRE bytes only, across attempts — never hash disk bytes into it, or `ErrDigestMismatch` stops meaning "the registry served wrong content" (the resume verify is structurally separate: `verify` returns `(bool, error)` and a mismatch is never an error value). `done == part.Size` restarts the part whole (an unsatisfiable range earns a 416, which stays untagged terminal: it proves the blob is shorter than the manifest). `Sink.Size` is read once, BEFORE the unconditional `Truncate` — the order is contract, Truncate destroys the evidence. Nothing is recorded between runs; a rerun re-hashes the whole partial (accepted, documented) and a wrong-size partial is truncated and fully fetched, never discarded.
- Retry classification contract (phase 3, `.journal/004/DESIGN.md`): adapters tag transient failures with `retry.Transient(err, after)`; untagged = terminal; `retry.Do` reads cancellation off ctx.Err(), NEVER off the error's shape — net/http renders dial/header/client timeouts as errors matching context.DeadlineExceeded while the caller's ctx is alive, so an errors.Is guard silently kills retries for the most common transient failures. A caller-supplied http.Client Timeout bounds one attempt (retried with a fresh window). Retry-After is a floor clamped by the one 30s cap, in the core.
- The orchestrator is the only retrier and never retries the disk: pull tags registry reads (readError), push tags its source reader (sourceError) and unwraps it after a failed Put — a source dying mid-upload otherwise surfaces through client.Do looking like a broken connection and gets tagged transient by the adapter.
- Parallel Go tests doing real HTTP need per-test transports: httptest.Server.Close closes http.DefaultTransport's idle connections as a courtesy, so tests sharing the default transport break each other mid-flight (bit us in CI on PR #21).
- `httptest.Server.Close()` is the happens-before barrier for handler-side bookkeeping (it blocks until the last handler returns). Proxy records filed after `ReverseProxy.ServeHTTP` returns are NOT ordered against the client finishing — the client sees the last body byte first; a measured 8 ms handler deschedule flipped e2e assertion rows red until settle-before-assert barriers went in (PR #27). Anything asserted from proxy records needs the barrier.
- `GOOS=windows go vet ./...` type-checks `_test.go` files; the `build-windows` gate (`go build`) does not — unix-only syscalls in test files (Setpgid, syscall.Kill) need build-tagged shims or the windows stance silently rots (bit us on PR #27's first CI run candidate).
- toxiproxy bandwidth toxics are PER-CONNECTION: four workers move 4x the configured rate. Divide by worker count when throttling manual gates.
- The frozen `-debug` grammar's `http>`/`http<` lines carry no `bigoci:` prefix and a sequence number before the verb — grep `^http> .*class=blob-write`, never the verb.
- net/http strips only Authorization/WWW-Authenticate/Cookie* across cross-host redirects (`makeHeadersCopier`), so `Range` survives a presigned redirect to object storage — phase-5 relevant, verified against go1.26.4.
- Fault-injection e2e discipline (e2e_flaky_test.go is the template): schedule damage removal causally off observed traffic, never on a timer (full jitter makes fixed windows flaky: P(three sleeps sum < 1.2s) ≈ 3.6%/unit); vary content per scenario (zot dedupes blobs globally and answers HEAD cross-repo — reused bytes mean nothing uploads); scope evidence per toxic (reset-at-connect kills the cheap HEAD probe, so only a toxic the probes survive can prove an upload retried mid-body); expect full attempt counts only on the first-exhausted unit (errgroup cancels peers mid-backoff; measured 4/3/3/3).
- The reference CLI lives in `cli/` (own module, local replace to the core; never published). Its `-debug` line grammar, fixed-shape summary line, and exit-code table (3/4/5 sentinels; 6/7 reserved for the future `ErrUnauthorized`/`ErrPartTooLarge` — keep those names) are FROZEN contracts the manual gates grep; treat changes as breaking. cli lint runs with `--disable gomoddirectives` (mandatory local replace) and both lint tasks need `--allow-parallel-runners` (moon parallelizes them; golangci-lint's instance lock otherwise fails CI).
- Auth contract (phase 5, `.journal/006/DESIGN.md`): Authorization is stamped at request-build time in `internal/oci` under the caller's transport (the tap sees everything, token exchanges included, as `class=other`); the `Credentials` port (four-field Credential — a two-string port silently downgrades identity tokens to anonymous) is defined in oci and implemented by `internal/auth`, which wraps ONLY oras-go's credentials store — its `auth.Client` was rejected on evidence (refresh-by-resend violates the spent-body rule, no exported token fetch, expiry-less cache). The refusal rule: transient iff handling changed what the next request presents; an unproven refresh's refusal is denied, denied is absorbing — bad creds burn zero budget, expiry self-heals; a 403 WITH a challenge takes the refresh path (GHCR answers invalid bearers 403), a bare 403 is terminal ErrUnauthorized (WAF misreport admitted). Expiry is proactive on the monotonic clock (expires_in default 60, margin min(30s, life/2)) — the long-push gate measured five seamless re-mint cycles, so an expired token never reaches the registry.
- Redirect contract (phase 5): auto-follow is OFF for every request; the adapter follows manually, <=3 hops, GET/HEAD only, each hop a fresh request carrying exactly {Range, Accept} (Range also suppresses Go's auto-gzip) plus Authorization iff EXACT same-origin (scheme + case-insensitive host + effective port — Go's domain-or-subdomain rule is the leak being closed); redirect client has no Jar; upload-session Locations validated the same way with the credential stripped off-origin. Off-registry 401/403/404/410 are TRANSIENT via an unexported redirectError matching NO sentinel (an expired signature is not ErrUnauthorized/ErrNotFound). No error may name a signed URL: statusDetail skips 3xx bodies (servers echo the Location into them), scrub drops url.Error's full-URL rendering, redirectError carries no storage body (S3 SignatureDoesNotMatch echoes a live session credential).
- Agent-made commits can inherit `josh@gilman.io` (harness context) instead of the GitHub-verified `joshuagilman@gmail.com`; the master ruleset requires verified signatures, so such commits block merges (squash does not launder them). Commit agent work yourself or audit `git log --format=%ae` before pushing.
- `go build` inside a git worktree can stamp `vcs.revision` as the parent checkout's commit — binary provenance (the CLI's first `-debug` line) can name the wrong commit; cross-check with `go version -m`.
- Rely only on universally supported registry operations (monolithic blob PUT, blob GET). Chunked upload, v1.1 resumable push, and Range support vary by registry; the design deliberately avoids depending on them. Registry-variance case files: GHCR rejects multi-chunk uploads (design), zot v2.1.9 loses zero-length blobs to dedupe hardlinking (e2e pins v2.1.20).
- go-digest registers no hash: every non-test package that validates or computes digests needs a `crypto/sha256` blank import, or production binaries reject all digests while tests pass (testing links the hash). Bit us once; recurs per new package.
- Manifest canonical encoding is a cross-implementation contract (format.md Determinism): compact JSON, sorted annotation keys, no HTML escaping (SetEscapeHTML(false)), sha256 everywhere in v1. Golden tests pin the bytes — never switch them to JSONEq.
- Deliberate seams: every phase-4/5 reservation is consumed (exit 6/ErrUnauthorized live; ErrPartTooLarge exit 7). Phase 6 decided AGAINST worker self-tuning (zero 429/503 in 333 measured transfers incl. 8 workers on GHCR — data in docs/reference/benchmarks.md and design.md Open Questions), so the retry tag deliberately keeps `after` with no overload kind; extend only if a registry is ever observed throttling. Identity-token (ACR) credentials are refused loudly, not supported — the OAuth2 refresh_token grant is the named follow-up. The split rule lives only in plan.New — keep it single-gated.
- Benchmarks are manual-only by decision (no nightly job): the `bench/` module (spec-driven, `-resume`, status-counting transport) plus `bench/latitude/` runbook rerun the matrix; measured field facts live in docs/reference/benchmarks.md. A warm re-push measures the client's single-pass read+sha256 floor (~1125 MB/s on 6 cores), network-free — and short transfers understate pull throughput (2GiB ~650 vs 16GiB ~900+ MB/s on the same path), so deciding matrices need target-sized files. Latitude/lsh: JSON answers are single-element arrays, a create can report "on" then 404 minutes later (poll for not_found), and same-site plan stock can vanish between two creates.
- Local toolchain quirks: `mise x --cd` CHANGES the child's cwd (never use in agent prompts — corrupted go.mod twice); `mise x -- moon run` collides with proto's Go via GOROOT — use `mise x -- env -u GOROOT moon run ...`.
- Release automation: release-please on plain GITHUB_TOKEN; pre-1.0 versioning is organic (feat -> minor). Do not set the manifest baseline to 0.0.0 (release-please bootstrap trap proposes 1.0.0) and do not re-enable bump-patch-for-minor-pre-major. The Actions "can create PRs" permission lives outside repository-settings.toml (Actions permissions API, org + repo). Release PR #11 reads 0.1.0 and stays open until the first release is cut deliberately.
- GHCR field facts (measured, session 006): presigned storage ACCEPTS a leaked bearer (200) — no-leak gates must read `auth=none` off the -debug log presence-required, never infer from success; invalid bearers answer 403 (401 only for absent credentials); anonymous tokens carry no expires_in (spec default 60s; authenticated TTL ~90s inferred from the 60s re-mint cadence); upload sessions live at `/blobs/upload/` (SINGULAR) so session PUTs classify class=other and GHCR pushes read `blob-write=0` — count `/token` request lines for exchange evidence, never class=other; a challenged transfer's summary reads failed>=1 (the protocol's own 401s).
- Test env isolation is per-package on purpose: the cli suite's TestMain empties PATH (credential helpers unexecutable by construction) and isolates DOCKER_CONFIG/HOME/USERPROFILE; the root e2e suite isolates DOCKER_CONFIG ONLY — testcontainers resolves rootless Docker sockets and image-pull credentials through HOME and PATH, so redirecting them breaks other machines. The conformance suite (cli, `-tags conformance`, workflow_dispatch conformance.yml) reads BIGOCI_CONFORMANCE_DOCKER_CONFIG because TestMain wipes DOCKER_CONFIG before tests run.
- golangci-lint's cache survives worktree removal and emits phantom findings citing deleted `.wt/*` paths (bit twice in session 006): run `golangci-lint cache clean` before diagnosing a lint failure that names another worktree. And never pipe the check that gates a commit — `moon run root:check | tail` returns tail's exit status, which once let a commit land past a red check.

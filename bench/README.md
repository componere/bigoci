# bench

Measurement tooling for bigoci: a harness that measures push and pull
throughput over a matrix of part sizes, worker counts, and file sizes, and
turns the numbers into the library's defaults. Never published, never
released; the local `replace` in `go.mod` makes it uninstallable from a
module proxy on purpose.

The harness drives only the library's public API. It does not provision
servers, start registries, or schedule anything.

## Usage

```sh
bench run -spec specs/stage1.json -out results/stage1.jsonl [-resume] [-endpoint zot=10.0.0.2:5000]
bench summarize -in results/stage1.jsonl
```

`run` walks the cross-product a spec describes — targets x part sizes x
workers x file sizes x iterations — and appends one JSONL row per timed
scenario. Every iteration generates a unique seeded fixture, so a
deduplicating registry can never quietly skip an upload. A failed cell is
recorded and skipped past, never fatal; `-resume` re-runs only what is
missing or failed, which is what makes an interrupted paid run cheap.
`-endpoint` substitutes real addresses for the placeholders the checked-in
specs carry.

`summarize` renders a results file as Markdown: one median-MB/s grid (part
sizes down, workers across) per registry, file size, and scenario, then a
long-form statistics table. Throughput is decimal MB/s, the unit the design
document quotes.

## Scenarios

Scenarios are phases within one iteration, always in this order, and the
spec's `scenarios` list picks which are timed:

- `cold-push` — push freshly generated bytes to an empty repository: the
  real upload path.
- `warm-push` — push the same file again to a second tag: the per-part
  existence-check path, nothing else.
- `cold-pull` — pull the artifact to a fresh path: the real download path.
  Pull size is checked every iteration; content is re-hashed under the
  spec's `verify` policy (`first` by default).

The cold push executes even when not selected — later phases need the
artifact — it just goes unrecorded.

## Local development loop

```sh
docker run -d --rm --name bench-zot -p 5555:5000 \
  -v "$PWD/latitude/zot-config.json:/etc/zot/config.json:ro" \
  ghcr.io/project-zot/zot:v2.1.20
go run . run -spec specs/smoke.json -out results/smoke.jsonl -endpoint zot=localhost:5555
go run . summarize -in results/smoke.jsonl
docker stop bench-zot
```

The config mount matters — the image's default configuration refuses
anonymous access — and the port remap dodges macOS's AirPlay listener on
5000.

Unit tests (`go test ./...`) cover the spec grammar, matrix expansion,
fixture determinism, resume bookkeeping, and summarize rendering — no
network, no registry.

## Measurement sessions

The real numbers come from paid bare-metal runs; `latitude/README.md` is
the runbook. Results land in `results/` (gitignored) and are preserved in
the session journal, not the repository.
